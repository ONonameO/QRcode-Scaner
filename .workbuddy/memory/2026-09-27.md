## 调试：修复「所有本地识别都失败」
- 现象：本地离线解码全部失败（auto 模式静默回退草料、local 模式硬失败）。
- 根因 1（主因）：`setupOffscreen()` 只在首次创建 offscreen，从不重建。offscreen 承载本地解码的 `chrome.runtime.onMessage` 监听器；若其实例陈旧（代码更新前创建）或首条消息发出时尚未就绪，则无监听者应答 → `decodeOffline` 抛错 → 全部本地失败。
  - 修复：引入 `OFFSCREEN_VERSION` + `ensureOffscreen()`（版本不符则 close 后重建）；`decodeOffline` 在无响应(`!resp`)时 `recreateOffscreen()` 并再试一次（自愈）。未处理的 action 默认 `return false`，避免误占消息通道。
- 根因 2（次要/画质）：`preprocessViaCanvas` 二值化用 `lum === 0` 阈值，真实截图/照片暗模块很少恰好为 0，导致二维码被整体置白。改为 `lum < 128` 标准全局阈值。
- 改动：`background.js`（ensureOffscreen/recreateOffscreen/self-heal/offscreenVersion）、`qr-decoder.js`（阈值）、`offscreen.js`（增加 console 日志）。
- 验证：3 个 JS 语法 OK；vendored `reader/index.js` 在 Node 可正常 import（`readBarcodesFromImageFile` 为函数，确认无 import-time 崩溃）；其 wasm 实例化在工厂函数 `w()` 内懒执行，不在 import 期。

## 修正3：manifest 的 `wasm-eval` 关键字被拒，改用 `unsafe-eval`
- 用 `'wasm-eval'` 导致扩展直接加载失败：`Insecure CSP value "'wasm-eval'" in directive 'script-src'`。Chrome 的 `extension_pages` CSP 不认 `'wasm-eval'`，只认 `'self'` 与 `'unsafe-eval'`。
- 修复：改为 `"extension_pages": "script-src 'self' 'unsafe-eval'; object-src 'self'"`。JSON 已校验合法。
- 教训：扩展页放行 WASM 只能用 `'unsafe-eval'`（更宽松、会放开 JS eval），不能用 `'wasm-eval'`。

## 修正2：WASM 被扩展 CSP 拦截（manifest 需放行 wasm-eval）
- 上一轮修掉 CANVAS 后，offscreen 能创建、消息能到达；用户再报：`WebAssembly.instantiate()` 被 CSP 拒绝（`script-src 'self'` 不含 wasm-eval）。
- 修复：manifest.json 增加 `"content_security_policy": { "extension_pages": "script-src 'self' 'wasm-eval'; object-src 'self'" }`。优先用更安全的 `wasm-eval` 而非 `unsafe-eval`。JSON 已校验合法。
- 说明：zxing 的 wasm 编译发生在 offscreen 文档（属 extension_pages），故需在此 CSP 放行。

## 修正：真正的根因是 `reasons` 含非法值 `CANVAS`
- 用户贴回控制台报错：`offscreen.createDocument` 在 `reasons` 的 index 2（`'CANVAS'`）报错，合法值集合不含 CANVAS。说明 **createDocument 从功能上线起就每次抛错、offscreen 从未成功创建** → 本地解码监听器从不存在 → 全部本地识别静默失败/回退。这才是"所有本地识别都失败"的真凶（之前的版本/自愈只是兜底，未触及此阻塞）。
- 修复：`background.js` 两处 `createDocument` 的 `reasons` 由 `['DOM_PARSER','IFRAME_SCRIPTING','CANVAS','BLOBS']` 改为 `['DOM_PARSER','IFRAME_SCRIPTING','BLOBS']`。Canvas 2D 在 offscreen 文档里天然可用，无需专门原因。已 grep 确认无残留 CANVAS，`node --check` 通过。
